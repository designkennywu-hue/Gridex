# Gridex recording engine

Migrated from Kenny’s local Cord/Recorder on 2026-10-20. `engine.cjs` is instantiated by the Gridex server and opens no second port. The capture helper, Swift source, MP3 encoder, and transcription models live here; the old Record folder and service are not required. Models were hard-linked on the same disk to avoid duplicating 1.6 GB; removing the old folder does not remove these links. Treat model files as immutable; replace by a new file plus rename when updating.

Recordings and sidecars are saved in the knowledge root’s inbox. Transcription uses the installed whisper-cli and summaries use local Ollama. Closing the browser does not stop a capture; reopening Gridex recovers the session. The Gridex server must remain running.

The vendored lamejs encoder is distributed separately; its upstream notice and attribution are beside it in public/vendor/. Native helper rebuilt from capture/cord-capture.swift with swiftc when needed. Models/bin are runtime assets, excluded from Git.


## Automatic Zoom capture

Kenny requested local automatic Zoom capture on October 21. Gridex runs a background detector every five seconds while its existing login service is running. This is a native desktop Zoom detector, not a Zoom cloud-recording integration and not a Codex scheduled task. `.zoom-autorecord.json` at the knowledge root stores the enabled preference; the expanded recorder has a shared Checkbox to change it. No new launch agent is installed.

`capture/zoom-status.swift` reads accessibility controls only for the `us.zoom.xos` app. It recognizes the actual Zoom meeting window (`zm.meeting.window.main`) even when the toolbar is hidden, or requires both Leave/End and Audio/Mute controls. Known waiting/joining controls are excluded; merely opening Zoom or a calendar event does not qualify. It does not request permission automatically, inspect other apps, or save window contents. English control labels are currently supported; actual join/leave, minimized and full-screen behavior need a live Zoom test. Accessibility failure/ambiguity reports unknown, never a confirmed join. In this login-service installation, macOS attributes the detector permission to `node`; Kenny enabled that entry in Privacy & Security → Accessibility during setup. Build the detector with `swiftc -O -o bin/zoom-status capture/zoom-status.swift`.

The `zoom-autorecord.mjs` controller requires a stable positive signal before starting the existing local system-audio + microphone capture. A confirmed departure lasting 15 seconds stops/saves the owned session; sustained unknown detection for 60 seconds saves it with an attention state. A four-hour limit also saves automatically. Recording identity prevents stopping or claiming a manual recording. A manual stop suppresses auto-restart until a confirmed departure. Disabling auto-capture saves only an automatically owned session. Existing recording state and errors remain visible in the recorder.

Saved audio enters the existing local transcription, summary, speaker and paragraph pipeline. Product/design knowledge ingestion remains the authorized 08:30 daily pending-recording workflow; no immediate knowledge synthesis or project edits are implied. Originals remain in inbox until that workflow processes them. Let meeting participants know about local recording; Zoom’s recording indicator is not controlled by Gridex.
